# 구글 드라이브 시트에서 Meta 광고 A/B 테스트 만들기

구글 스프레드시트에 적어 둔 광고 정의와 드라이브 폴더의 소재 파일로 Meta 광고를 만듭니다. 광고 생성은 개발자 문서의 **MCP**에 있는 공식 광고 서버 `https://mcp.facebook.com/ads`로 합니다. 같은 화면의 WhatsApp, 페이지 API, 픽셀은 광고 생성 경로가 아닙니다. 같은 테스트명의 변형은 각각 광고세트가 되고, 비즈니스 ID가 있으면 A/B 실험을 만듭니다.

광고는 항상 **일시중지**로 만들어집니다. 시트에서 `게시`로 적고 `--allow-active`를 준 경우에만 실제로 켜지며, 그때부터 광고비가 지출될 수 있습니다.

## 시트가 하는 일

한 행이 광고 하나입니다.

| 열 | 설명 |
| --- | --- |
| 테스트명 | 같은 이름끼리 캠페인 하나로 묶입니다. |
| 변형 | A, B처럼 광고세트를 나눕니다. |
| 동작 | `생성`, `일시중지`, `게시` |
| 캠페인명, 목표 | 목표는 트래픽, 매출, 리드, 인지도, 참여, 앱설치 |
| 일예산 | 광고세트 일예산. 원화 계정은 원 단위, 달러 계정은 센트 단위 |
| 국가 | `KR` 또는 `한국`. 여러 국가는 쉼표로 구분 |
| 소재파일 | 드라이브 폴더 안의 파일명, 파일 ID, 파일 URL. mp4, mov도 사용할 수 있습니다. |
| 썸네일파일 | 비우면 동영상 첫 장면을 썸네일로 씁니다. 원하는 장면이 있으면 이미지 파일명을 적습니다. |
| 페이지ID | 비우면 `META_PAGE_ID`를 사용 |
| 픽셀ID | 목표가 매출일 때 필요 |
| 캠페인ID, 광고세트ID, 광고ID, 실험ID, 오류 | 실행 후 프로그램이 채웁니다. 이미 ID가 있으면 다시 만들지 않습니다. |

예시는 `examples/ads_template.csv`입니다. 이 파일을 구글 시트에 올려도 되고, 같은 열 이름으로 새 시트를 만들어도 됩니다.

## Meta 비즈니스 스위트에서 찾을 값

비즈니스 포트폴리오 `Hy_hy_teamdata`를 선택한 뒤, 왼쪽 아래 톱니바퀴를 엽니다. 메뉴가 두 개로 나뉩니다.

**비즈니스 설정**을 먼저 엽니다. 사람, 페이지, 광고 계정을 한 포트폴리오에서 묶는 화면입니다.

- 비즈니스 정보 또는 비즈니스 포트폴리오 정보의 ID를 `META_BUSINESS_ID`에 넣습니다. A/B 실험을 만들 때 필요합니다.
- 계정, 페이지에서 광고에 쓸 페이지를 고르고, 그 페이지 ID를 `META_PAGE_ID` 또는 시트의 페이지ID 열에 넣습니다.
- 사용자, 시스템 사용자에서 사용자를 추가합니다. 역할은 직원으로 둡니다. 관리자 역할 토큰은 광고 MCP 서버가 거절합니다.
- 그 시스템 사용자에 광고 계정은 광고 관리, 페이지는 콘텐츠 또는 광고 권한을 할당합니다.
- 토큰을 만들 때 `ads_mcp_management`와 `ads_management`를 포함합니다. 이 값이 `META_ACCESS_TOKEN`입니다.

**광고 계정 설정**은 그다음입니다. 청구, 결제 수단, 광고 계정 권한을 보는 화면입니다.

- 광고 계정 ID를 `META_AD_ACCOUNT_ID`에 넣습니다. `act_`로 시작하지 않아도 실행할 때 붙입니다.
- 시스템 사용자가 이 광고 계정에 들어 있는지 확인합니다.
- 나중에 광고를 게시하려면 결제 수단이 등록되어 있어야 합니다. 생성만 할 때는 광고가 일시중지라 바로 지출되지 않습니다.

## 준비

1. [Meta 개발자 앱](https://developers.facebook.com/apps)에서 사용 사례 `Create & manage ads with ads MCP server`를 추가합니다.
2. 위에서 만든 직원 시스템 사용자 토큰을 `META_ACCESS_TOKEN`에 넣습니다.
3. 그래프 API로 직접 호출하려면 `.env`에 `META_TRANSPORT=graph`를 넣습니다.
4. 구글 클라우드에서 Sheets API와 Drive API를 켜고 서비스 계정 JSON을 만듭니다.
5. 광고 시트를 서비스 계정 이메일에 편집자로 공유합니다.
6. 소재가 들어 있는 드라이브 폴더도 그 이메일에 뷰어로 공유합니다.
7. `.env.example`을 `.env`로 복사하고 ID와 토큰을 채웁니다.

내 드라이브에 서비스 계정을 공유하지 않고 직접 접근하려면 OAuth 클라이언트 JSON을 `GOOGLE_OAUTH_CLIENT_SECRETS`에 두고 한 번 로그인합니다.

```bash
pip install -e .
ab-test auth-google
```

## 실행

미리보기는 Meta에 아무것도 만들지 않습니다.

```bash
ab-test run --sheet examples/ads_template.csv
```

구글 시트를 쓰는 경우:

```bash
ab-test run
ab-test run --apply
```

시트에 실험이 여러 개면 테스트명으로 고릅니다. 이름을 빼면 시트에 있는 실험을 모두 실행합니다.

```bash
ab-test run --test 여름세일
ab-test run --test 여름세일 --test 겨울세일 --apply
```

이미 만들어진 광고를 시트에서 `게시`로 바꿔 켜려면 다음을 사용합니다. 이 명령은 광고비를 지출할 수 있습니다.

```bash
ab-test run --apply --allow-active
```

결과 ID는 시트에 다시 기록됩니다. 같은 시트로 다시 실행하면 이미 있는 광고는 건너뜁니다.

로컬 소재 폴더로 시험할 때는 `--creatives examples/creatives`를 붙입니다. 폴더 파일명과 시트의 소재파일 열이 같아야 합니다.

광고를 누르면 열리는 페이지는 `landing/`입니다. `main`에 올리면 Cloud Build가 프로젝트 `fredit-dashboard`의 Cloud Run 서비스 `ab-landing`(서울 리전)으로 배포합니다.
