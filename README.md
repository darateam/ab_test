# 구글 드라이브 시트에서 Meta 광고 A/B 테스트 만들기

구글 스프레드시트에 적어 둔 광고 정의와 드라이브 폴더의 소재 파일로 Meta 광고를 만듭니다. 같은 테스트명의 변형은 각각 광고세트가 되고, 비즈니스 ID가 있으면 그 광고세트들로 A/B 실험을 만듭니다.

광고는 항상 **일시중지**로 만들어집니다. 시트에서 `게시`로 적고 `--allow-active`를 준 경우에만 실제로 켜지며, 그때부터 광고비가 지출될 수 있습니다.

## 시트가 하는 일

한 행이 광고 하나입니다.

| 열 | 설명 |
| --- | --- |
| 테스트명 | 같은 이름끼리 캠페인 하나로 묶입니다. |
| 변형 | A, B처럼 광고세트를 나눕니다. |
| 동작 | `생성`, `일시중지`, `게시` |
| 캠페인명, 목표 | 목표는 트래픽, 매출, 리드, 인지도, 참여, 앱설치 |
| 일예산 | 광고세트 일예산. 원화 계정은 원 단위, 달러 계정은 센트 단위 |
| 국가 | `KR` 또는 `한국`. 여러 국가는 쉼표로 구분 |
| 소재파일 | 드라이브 폴더 안의 파일명, 파일 ID, 파일 URL |
| 썸네일파일 | 동영상 소재에 필요 |
| 페이지ID | 비우면 `META_PAGE_ID`를 사용 |
| 픽셀ID | 목표가 매출일 때 필요 |
| 캠페인ID, 광고세트ID, 광고ID, 실험ID, 오류 | 실행 후 프로그램이 채웁니다. 이미 ID가 있으면 다시 만들지 않습니다. |

예시는 `examples/ads_template.csv`입니다. 이 파일을 구글 시트에 올려도 되고, 같은 열 이름으로 새 시트를 만들어도 됩니다.

## 준비

1. Meta 앱에서 `ads_management` 권한이 있는 시스템 사용자 토큰을 발급합니다.
2. 구글 클라우드에서 Sheets API와 Drive API를 켜고 서비스 계정 JSON을 만듭니다.
3. 광고 시트를 서비스 계정 이메일에 편집자로 공유합니다.
4. 소재가 들어 있는 드라이브 폴더도 그 이메일에 뷰어로 공유합니다.
5. `.env.example`을 `.env`로 복사하고 ID와 토큰을 채웁니다.

내 드라이브에 서비스 계정을 공유하지 않고 직접 접근하려면 OAuth 클라이언트 JSON을 `GOOGLE_OAUTH_CLIENT_SECRETS`에 두고 한 번 로그인합니다.

```bash
pip install -e .
ab-test auth-google
```

## 실행

미리보기는 Meta에 아무것도 만들지 않습니다.

```bash
ab-test run --sheet examples/ads_template.csv
```

구글 시트를 쓰는 경우:

```bash
ab-test run
ab-test run --apply
```

이미 만들어진 광고를 시트에서 `게시`로 바꿔 켜려면 다음을 사용합니다. 이 명령은 광고비를 지출할 수 있습니다.

```bash
ab-test run --apply --allow-active
```

결과 ID는 시트에 다시 기록됩니다. 같은 시트로 다시 실행하면 이미 있는 광고는 건너뜁니다.

로컬 소재 폴더로 시험할 때는 `--creatives examples/creatives`를 붙입니다. 폴더 파일명과 시트의 소재파일 열이 같아야 합니다.
